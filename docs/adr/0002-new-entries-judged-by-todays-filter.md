# New Entries are judged by applying today's Digest Filter to both snapshots

A New Entry is an Uncovered Departure that matches the current Digest Filter in the latest snapshot but did not match that same filter in the snapshot taken at the previous Digest. We store the full Uncovered list per snapshot (not just "already notified" IDs) so the comparison can be re-run under whatever the filter is today. Alternatives rejected: diffing filtered lists as they were sent (editing the filter would flood the next Digest with old Departures), and diffing only the unfiltered Uncovered list (a Departure crossing the minimum-Participants threshold, or drifting into the departure window, would never be reported).

Areas and Countries come from the catalogue at read time, so a Departure whose Itinerary was not in the catalogue when it was crawled has none and fails any Area/Country Digest Filter; once the catalogue catches up it would match on both sides and never be reported. Each snapshot Departure therefore records a `catalogued` flag, and when the filter constrains Areas or Countries a baseline row with `catalogued` false is treated as unknown, not as previously matching. Without such a constraint the catalogue is irrelevant and the normal rule applies, so a permanently uncatalogued Departure is not reported every day.

An empty snapshot (an accepted drop to zero Departures) is never recorded as the baseline: the Digest keeps the previous baseline, because otherwise the recovery of a broken API would report every Departure as a New Entry.
